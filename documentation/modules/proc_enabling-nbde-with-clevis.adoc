= Enabling Network-Bound Disk Encryption with Clevis 

[role="_abstract"]
When you enable Network-Bound Disk Encryption (NBDE) with Clevis, the Tang server manages the keys for Linux Unified Key Setup (LUKS)-encrypted disks during a migration. If you do not use NBDE to migrate LUKS-encrypted disks from your source environment, you can decrypt LUKS-encrypted devices either by selecting an existing Secret manifest containing the decryption passphrase or by entering passphrases manually.

You can configure LUKS disk decryption either in the {project-short} UI or in the YAML file for your migration plan:

* In the {project-short} UI, you can select only one decryption method per migration plan, which applies to all VMs in that plan.
* In the YAML file for your migration plan, you can combine different decryption methods and apply them to selected VMs in the same plan.

.Prerequisites

For NBDE with Clevis:

* The Tang server is accessible from your OpenShift cluster and from the migration network.
* You have a LUKS key slot bound to the Tang server policy.
+
NOTE: For {project-short} to access the keys from the Tang server, the keys must be on a different subnet range than a user-defined network (UDN).

For Secret manifest or manual passphrase:

* You have the LUKS decryption passphrase available.
* Optional: If you create a `Secret` manifest to provide the decryption passphrase, the secret must have the `Opaque` type, reside in the namespace of the migration plan, and contain one passphrase per data entry. For details, see xref:proc_creating-plan-wizard-vmware_{context}[Creating a VMware vSphere migration plan by using the MTV wizard].

.Procedure
. Configure disk decryption in the {project-short} UI.
.. In the Create migration plan wizard, navigate to *Other settings* under *Additional setup* in the left navigation pane.
.. Select the decryption method for LUKS-encrypted disks:
+
* For NBDE with Clevis: Select *Use NBDE/Clevis*.
* For Secret manifest or manual passphrase: Add passphrases for LUKS-encrypted devices or select a Secret manifest.
.. Click *Next*, and verify your selection under *Other settings (optional)*:
+
* For NBDE with Clevis: Verify that *Use NBDE/Clevis* shows as *Enabled*.
* For Secret manifest or manual passphrase: Verify that the Secret manifest or passphrases are listed.
.. When you create your migration plan, click *Migration plans* in the left navigation menu, and open the *Plan details* page for your migration plan.
.. Click the *Edit* icon for *Disk decryption* under *Plan settings*.
.. Verify your decryption method:
+
* For NBDE with Clevis: Verify that *Use network-bound disk encryption (NBDE/Clevis)* is selected.
* For Secret manifest or manual passphrase: Verify that the selected Secret manifest is configured or that passphrases for LUKS-encrypted devices are added. 

. Configure disk decryption in the YAML file.
.. Click *Migration plans* in the left navigation menu and open the *Plan details* page for your migration plan.
.. Click the *YAML* tab to open the `Plan` custom resource (CR) for your migration plan.
.. For each VM under `vms` in the YAML file, enter the decryption method. In this example, you set `nbdeClevis` as the decryption method for `vm-1`, a LUKS passphrase secret for `vm-2`, and no encryption method for `vm-3`:
+
Example:
+
----
vms:
  - id: vm-1
    name: vm-1-esx8.0-rhel8.10-raid1
    targetPowerState: on
    nbdeClevis: true
  - id: vm-2
    name: vm-2-esx8.0-rhel8.10-raid1
    luks: { name: 'test-secret-1' }
  - id: vm-3
    name: vm-3-esx8.0-rhel8.10-raid1
----

.Troubleshooting
* For information about LUKS or Clevis configuration on the source VM, see link:https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/10/html/security_hardening/configuring-automated-unlocking-of-encrypted-volumes-by-using-policy-based-decryption[Configuring automated unlocking of encrypted volumes by using policy-based decryption] in the RHEL _Security hardening_ guide.
